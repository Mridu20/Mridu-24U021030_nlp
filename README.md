## 📌 Executive Summary

Large Language Models (LLMs) used directly as recommendation systems suffer from severe **hallucinations**: they invent non-existent movie titles, fabricate cast and release details, hallucinate plot points, and attempt to answer out-of-domain or gibberish prompts rather than abstaining.

This project implements an end-to-end **Retrieval-Augmented Generation (RAG)** movie recommendation system that mathematically and architecturally guarantees **0% item hallucination** and validates explanation faithfulness using Natural Language Inference (NLI).

## 🚀 Key Features

1. **Guaranteed Zero Item Hallucination (`0.0%`)**:
   - The LLM does not generate freeform titles. Instead, it operates over a pre-retrieved candidate pool of 30 items.
   - Structured JSON schema enforcement with strict `enum` constraints ensures the LLM can only select real `movie_id` values from the retrieved set.
   - Movie metadata (titles, years, genres) is hydrated directly from the ground truth database (`catalog.csv`), never from model generations.

2. **Semantic Dense Retrieval**:
   - Movie metadata (title, genre, plot synopsis) is mapped into a normalized embedding space using `sentence-transformers/all-MiniLM-L6-v2`.
   - Fast cosine similarity search powered by a `faiss.IndexFlatIP` index over ~9,600+ movies.

3. **Confident Abstention Mechanism**:
   - If the top candidate's cosine similarity score falls below `MIN_SCORE = 0.25`, the system gracefully abstains from making arbitrary guesses on nonsense or out-of-domain inputs.

4. **NLI-Verified Explanations (96% Faithfulness)**:
   - Reasons generated by the LLM are cross-checked against the canonical catalog plot summary using `cross-encoder/nli-deberta-v3-base`.
   - If the reason contradicts the stored premise (`label == contradiction`), the explanation is discarded and safely replaced with the verified catalog description.

5. **Interactive Web Application**:
   - Built with **Streamlit** for real-time querying, visual presentation of recommendations, and transparency tags indicating whether explanations passed NLI verification.

## 🔬 Methodology & Algorithmic Workflow

### 1. Candidate Generation
Given query $q$:
$$\mathbf{e}_q = \text{Normalize}(\text{SentenceTransformer}(q))$$
FAISS computes inner products over normalized document embeddings $\mathbf{e}_d$ (equivalent to cosine similarity):
$$\text{Sim}(q, d) = \mathbf{e}_q \cdot \mathbf{e}_d$$
Candidates with scores $\ge 0.25$ are retained (top-30).

### 2. Constrained Decoding
The prompt and candidate metadata are passed to Llama 3.2 with strict JSON Schema validation:
```json
{
  "movie_id": {
    "type": "integer",
    "enum": [candidate_ids...]
  },
  "reason": {
    "type": "string"
  }
}
```
Because `enum` is enforced at token generation time, the model cannot physically output an out-of-catalog ID.

### 3. Explanation Validation
Let Premise $P$ be `"{Title} ({Year}). Genres: {Genres}. {Description}"` and Hypothesis $H$ be `Reason`:
$$\text{NLI}(P, H) \in \{\text{Contradiction}, \text{Entailment}, \text{Neutral}\}$$
If $\text{NLI}(P, H) = \text{Contradiction}$, the candidate's explanation is rejected and reverted to the verified catalog plot.
